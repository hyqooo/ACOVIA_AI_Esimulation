# minutes/｜議事録

## 目的
経営会議の記録。**発言ログそのものが主役**であり、結論の要約はその後に短く添える程度でよい（`../keiei-simulation-brief.md` の指示）。

## 運用ルール
- 1会議1ファイル：`YYYY-MM-DD-議題スラッグ.md`
- 議題は1回につき1つ。複数の議題を1回の会議に詰め込まない
- 参加は、その議題に関係が深い**3〜4部署**に絞る。全部署を毎回呼ばない
- **全員が同じ結論に相槌を打つだけの会議にしない。** 最低1回は、意見の対立か懸念の表明を入れる
- 意見が割れたまま終わってよい。その場合は「割れたまま持ち越し」と書く
- 誰も言っていないことを書かない。言及がなかった論点は「言及なし」と書く

## 書式

```
# YYYY-MM-DD｜議題：〇〇

参加：【CEO】【CFO】【COO】【VC】
進行：【秘書】

---

## 議題
（1文。判断を求める形にする。「〜について」ではなく「〜をどうするか」）

## 発言ログ

【CEO】……

【CFO】……

【VC】……

（※ 発言は要約せず、その部署の視点・口調で書く。各部署のCLAUDE.md参照）

---

## 対立した点
（誰と誰が、何をめぐって割れたか）

## 決着
（多数決／CEOの最終判断／秘書の仲裁／割れたまま持ち越し、のいずれか。決着の理由まで書く）

## 決まったこと

## 決まらなかったこと

## 次回への持ち越し課題

## 派生したタスク
（`../todo/open-tasks.md` に追記した番号を書く）

## 派生した意思決定
（`../decisions/` に追記したファイル名を書く）
```

## 注意
この議事録は、後から「なぜそう決めたのか」を再現するために書く。**決着の理由を省略しない。** 結論だけが残ると、状況が変わったときに再検討できなくなる。
