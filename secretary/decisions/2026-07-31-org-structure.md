# [D-001] AI経営チームの組織を6部署で構築する

| 項目 | 内容 |
|---|---|
| 決定日 | 2026-07-31 |
| 関連する仮説 | 該当なし（組織設計） |

| 決定タイプ | 可逆 |
| 決めた人 | 社長（Hiroki）＝ 組織案を提示のうえ承認を取得 |
| 関連する議事録 | なし（会議前の構築フェーズ） |

## 決めたこと

AI経営チームの仮想組織を、以下の6部署で構築する。フォルダ＝部署、CLAUDE.md＝業務マニュアルとして扱う。

| フォルダ | 部署名 | 担当ロール |
|---|---|---|
| `secretary/` | 秘書室 | 秘書 |
| `ceo-cpo/` | 経営・プロダクト室 | CEO・CPO |
| `coo-chro/` | オペレーション・組織室 | COO・CHRO |
| `cfo-cmo/` | 財務・マーケティング室 | CFO・CMO |
| `legal-impact/` | 法務・倫理・社会的インパクト室 | 法務倫理・ソーシャルインパクト |
| `vc-review/` | 投資家レビュー室 | VC |

組織図は「社長（Hiroki）→ CEO（Claude Code）→ 各部署」。`ceo-cpo/` はCEO自身の執務室を兼ねる。

## 決めた理由

- 会社の憲法（`CLAUDE.md`）で定義済みの10役を、すべてカバーできる最小構成であるため
- 依頼書（`company-build-brief.md`）の「最初から作りすぎない」方針に沿うため。部署は、実務が発生した時点で秘書室が提案して追加する
- 各部署のCLAUDE.mdに「他部署とどこで対立するか」を明記した。経営シミュレーション側の依頼書が「全員が相槌を打つだけの会議にしない」ことを求めているため、対立構造を組織設計に埋め込んだ

## 検討したが採らなかった選択肢

- **CxOごとに10部署に分割**：各視点は純粋になるが、フォルダ数と管理コストが増える。3名の実在チームに対して過剰
- **4部署に集約**：軽量だが、`vc-review/` を財務側に統合すると「社内の反対者」としての独立性が失われる

## 再検討条件

以下のいずれかが起きたら、部署構成を見直す。

- 会議で、どの部署にも属さない論点が3回以上繰り返し出た → 部署の追加を検討
- 特定の部署が3か月以上、会議に呼ばれていない → 統合を検討
- サポーターが5名を超えた → サポーター育成室の追加を検討
- 医療機関・企業との契約が3件を超えた → パートナーシップ室の追加を検討

## わかったこと

各部署のCLAUDE.mdを起こす過程で、会社の憲法に書かれている未完了事項を洗い出したところ、**有償MVPの開始をブロックしている項目が5件**あることが判明した（`../todo/open-tasks.md` の T-001〜T-005）。いずれも安全・危機対応まわりであり、事業論点より前に置くべきものである。

90日Gateの検証開始日（2026年8月3日）までは3日しかない。
